# invalid-demo — Example C: invalid archives

Two harmless fixtures (each under 100 bytes, inert text) generated by
[`make-invalid.py`](make-invalid.py):

| File | What it is | Why it is invalid |
|---|---|---|
| [`not-a-gzip.tgz`](not-a-gzip.tgz) | Plain text named `.tgz` | Not gzip at all. A name is not proof of a format. |
| [`gzip-not-tar.tgz`](gzip-not-tar.tgz) | A valid gzip stream of plain text | The content is not a tar archive. |

There is no `report.json` here on purpose: an archive that cannot be read produces an
error, not a report.

## Reproduce

```bash
python3 -I examples/invalid-demo/make-invalid.py
```

```bash
node server/bin/audyssey.js analyze --tarball examples/invalid-demo/not-a-gzip.tgz
```

```bash
node server/bin/audyssey.js analyze --tarball examples/invalid-demo/gzip-not-tar.tgz
```

To see the API behavior as well, start the server (`npm run dev:server`) and run
[`run-invalid.sh`](run-invalid.sh), which prints every response. Needs no internet:
the archives are rejected before anything is looked up.

## Captured output

[`captured-output.txt`](captured-output.txt) is the real output of `run-invalid.sh`
(IDs and timestamps replaced by `<job id>` and `<time>`). In summary:

| Input | CLI | API |
|---|---|---|
| `not-a-gzip.tgz` | `Error: … (Archive is not gzip-compressed)`, exit code 2 | `400` `not-gzip` at upload, no job is created |
| `gzip-not-tar.tgz` | `Error: … (Malformed number in tar field "checksum")`, exit code 2 | `202`, then the job ends `failed` with code `unidentifiable-tarball`; `/report` answers `409 not-ready` |

In the dashboard the first is refused immediately and the second shows
"Analysis did not complete" with the server's message. The CLI wording ("Pass the
package name and version explicitly") is the CLI's; the dashboard has no such option.
Real archive attacks (path traversal, links, bombs, corrupt headers) are exercised
by the automated tests, which build them in memory rather than committing them.
